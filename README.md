# shift-manager-firebase
シフト管理システムをFirebaseをWebで公開できるようにしました


スタッフの勤務希望の提出と、管理者によるシフト作成を支援するWebアプリです。スマートフォンやタブレットからの利用も想定し、ログイン認証とクラウドデータ保存を組み合わせています。

## 背景・目的

シフト作成では、スタッフごとの勤務希望、休業日、必要人数などを確認しながら調整する必要があります。本アプリは、勤務希望の入力とシフト管理を1つの画面にまとめ、シフト作成業務を支援することを目的に制作しました。

## 主な機能

- Firebase Authenticationによるログイン
- 管理者・一般利用者の役割に応じた機能制御
- スタッフ情報の登録・編集
- カレンダー形式での勤務希望の入力・確認
- シフトの自動生成と、生成後の手動調整
- 休業日やシフト生成条件の設定（管理者向け）
- データのJSON書き出し・読み込み（実装済みの範囲で確認）
- Firestoreを利用したデータ共有

## 権限設計

 操作  管理者  一般利用者 
 ログイン  ○  ○ 
 スタッフ情報の閲覧・編集 ○  ○ 
 勤務希望の閲覧・登録・編集  ○  ○ 
 シフトの閲覧  ○  ○ 
 シフトの自動生成  ○  × 
 生成条件・休業日などの設定  ○  × 

アプリ画面側の制御に加え、Firestoreセキュリティルールでも書き込み権限を制限しています。最終的な権限は、画面の表示だけではなくデータベース側でも確認する設計です。

### 現在の権限設計上の注意

現状は管理者用アカウントと一般利用者用アカウントを共有する運用を想定しています。そのため、一般利用者同士を個別に識別して「自分の勤務希望だけ編集可能」とする仕組みではありません。一般利用者の権限ではスタッフ情報・勤務希望のデータをまとめて編集できるため、実運用では個別アカウント化や本人単位のアクセス制御を追加する余地があります。

## データ設計

Firestoreでは、アプリデータを用途ごとのドキュメントに分けて保存します。

 コレクション / ドキュメント  主な内容 

 `users/{uid}`  ログインユーザーの役割（`admin` / `user`） 
 `employees/main`  スタッフ情報の配列 
 `requests/main`  勤務希望データ 
 `shifts/main`  確定シフトデータ 
 `settings/main`  生成条件、休業日、履歴、ID管理情報 


## セキュリティ上の取り組み

- Firebase Authenticationでログインを確認
- Firestoreセキュリティルールで役割に応じた読み書きを制限
- 管理者専用データ（シフト・生成条件等）は一般利用者からの書き込みを拒否
- 入力値をHTMLとして不用意に解釈させないよう、表示処理を確認する
- 実際の個人情報・パスワード・秘密鍵をソースコードやREADMEに記載しない
